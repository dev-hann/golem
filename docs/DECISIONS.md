# Architecture Decision Records

Chronological. Each ADR is immutable once accepted; superseding an ADR adds a new one referencing the old. New architectural decisions require a new ADR here, in the same change that implements them.

---

## ADR-0001: Build a new agent instead of contributing to opencode/jcode

- **Status:** Accepted (2026-09-26)
- **Context:** opencode is memory-heavy (Bun/TS runtime, ~500 MB+ RSS observed); jcode has sluggish state management. Both are established tools with large codebases whose core tradeoffs oppose the goals here.
- **Decision:** Build golem — a Go coding agent optimized for low memory and fast state handling.
- **Consequences:** We own maintenance (estimated 2–4 h/month steady-state, spiking when providers change models). Scope stays deliberately small; every feature must justify its maintenance cost.

## ADR-0002: Go, not Rust

- **Status:** Accepted (2026-09-26)
- **Context:** Rust would minimize memory further (~30–60 MB vs ~100–150 MB). But a coding agent is JSON-glue + network waiting; the bottleneck is LLM latency, not local compute. Rust's ownership/borrow machinery adds 1.5–3× development cost for dynamic JSON manipulation, which dominates this codebase.
- **Decision:** Go 1.25+.
- **Consequences:** GC pauses are irrelevant at this scale; `GOMEMLIMIT` caps RSS. Memory goal (≤150 MB) met with margin vs the 500 MB+ baseline of existing tools.

## ADR-0003: Client/server split — server owns all state

- **Status:** Accepted (2026-09-26)
- **Context:** A monolithic TUI dies with the terminal; long agent turns should survive client restarts. Future web/desktop clients need a stable surface.
- **Decision:** Long-lived agent server process; clients connect over a socket and render events. Sessions persist server-side.
- **Consequences:** Protocol becomes a product surface (see PROTOCOL.md). One extra process (~30–80 MB), acceptable within budget.

## ADR-0004: NDJSON codec over unix socket; transports are pluggable

- **Status:** Accepted (2026-09-26)
- **Alternatives considered:** HTTP+SSE (more moving parts, no benefit locally), gRPC (proto toolchain + codegen overhead unjustified for one local binary pair), WebSocket-only (needed later for web, not for local IPC).
- **Decision:** Line-delimited JSON in both directions. Default transport: unix domain socket. TCP and WebSocket listeners reuse the identical codec.
- **Consequences:** Debuggable with `curl`/`nc`; zero framework dependencies in the server; adding web support later requires a transport shim only, not a protocol change.

## ADR-0005: Official provider SDKs behind one thin interface; Z.ai via OpenAI-compatible endpoint

- **Status:** Accepted (2026-09-27)
- **Context:** Four providers needed: Anthropic, OpenAI, Z.ai (GLM), Ollama. Multi-provider frameworks (langchaingo, eino) add heavy abstraction contradicting the lightweight goal. Z.ai ships no official Go SDK, but its API is OpenAI-compatible (and Anthropic-compatible).
- **Decision:** `Provider` interface in `internal/llm`; adapters: `anthropics/anthropic-sdk-go`, `openai/openai-go`, `ollama/ollama/api`, and Z.ai as `openai-go` with `WithBaseURL` override.
- **Consequences:** Provider API changes surface in adapters only. New providers ≈ 100-line adapter + config entry.

## ADR-0006: Bubble Tea for the TUI

- **Status:** Accepted (2026-09-26; superseded in part by ADR-0035 for the v2 runtime)
- **Context:** Candidates: Bubble Tea (Elm-architecture, composable, de facto standard), tview (widget-rich, weaker state model), gocui (low-level, maintenance mode).
- **Decision:** Bubble Tea + lipgloss + bubbles — now the v2 line at `charm.land/*` per ADR-0035.
- **Consequences:** State management is explicit (Model/Update/View), which suits AI-driven development and testing.

## ADR-0007: MCP as the plugin system; reject Go `plugin` and custom plugin formats

- **Status:** Accepted (2026-09-27)
- **Context:** Extensibility is required (extra tools). Options: invent a plugin ABI (cost, no ecosystem), Go `plugin` .so (Linux-only, fragile version coupling), MCP (open standard, JSON-RPC over stdio, large existing server ecosystem).
- **Decision:** External tool plugins are MCP servers declared in config; golem ships an MCP client managing their lifecycle. Hooks (pre/post tool) are deferred. Internal providers/tools stay compile-time Go.
- **Consequences:** Plugin = separate process (isolation, any language). MCP client is ~200 lines if hand-rolled; adopting `modelcontextprotocol/go-sdk` instead requires an ADR.

## ADR-0008: Append-only JSONL session store; no database

- **Status:** Accepted (2026-09-27)
- **Context:** Sessions need crash-safe persistence, trivial inspection, and fast load — not queries. SQLite et al. add binary formats, migrations, and a dependency for zero benefit at single-user scale.
- **Decision:** One JSONL file per session under `~/.local/share/golem/sessions/`; events are appended before emission to clients; replay folds events into state.
- **Consequences:** The wire protocol and storage format are the same objects (see PROTOCOL.md). Bounded in-memory cache; cold sessions stream from disk.

## ADR-0009: Monorepo, single Go module; `pkg/golemclient` as the public client contract

- **Status:** Accepted (2026-09-27)
- **Context:** Future web/desktop clients must share the protocol without forking types. Multi-module workspaces add ceremony without need.
- **Decision:** One `go.mod`. Protocol types live in `pkg/golemclient` (importable by all clients). Future non-Go clients live under `apps/` outside the module build.
- **Consequences:** One version set; protocol changes are visible as compile errors in `golemclient`.

## ADR-0010: Approval gate with read-only whitelist

- **Status:** Superseded by ADR-0016 (2026-10-14)
- **Context:** Unattended shell execution is the primary risk of a coding agent.
- **Decision:** All shell-side-effect tools route through `internal/approval`. Configurable `auto_prefixes` (ls, cat, git status, grep, rg, …) run unprompted; everything else blocks on an `approval_request` until answered or timed out (120 s → deny). `all_auto` exists as a config-only escape hatch with documentation warnings.
- **Consequences:** One round-trip per sensitive command; acceptable. *(In practice the whitelist matched almost no real model-issued command line — redirections like `2>/dev/null` and chained segments forced prompts — turning the gate into per-call friction; see ADR-0016.)*

## ADR-0012: Layered TOML configuration

- **Status:** Accepted (2026-09-27)
- **Context:** Need global + per-project + env overrides; JSON lacks comments; YAML complexity unneeded.
- **Decision:** `BurntSushi/toml`. Precedence (low→high): built-in defaults → `~/.config/golem/config.toml` → `<project>/.golem.toml` → env (`GOLEM_*`) → CLI flags. Maps deep-merge; slices replace. Secrets use `ref:ENV_NAME` indirection or env directly — plaintext keys in files are warned against.
- **Consequences:** One parser dependency; schema documented in CONFIG.md.

## ADR-0013: Strict uniformity gates (lint, coverage, docs-as-code)

- **Status:** Accepted (2026-09-27)
- **Context:** Development is AI-driven across sessions; code uniformity and stable context are requirements, not preferences.
- **Decision:** golangci-lint with maximum practical strictness (gofumpt, revive strict, exhaustive, gosec, complexity gates, 120 cols); race-detector tests; 80% coverage floor in CI; docs under `docs/` are the source of truth and must change with behavior (enforced socially via AGENTS.md review gate).
- **Consequences:** Occasional lint friction is accepted as the price of uniformity.

## ADR-0014: One openai-compat adapter for openai, zai, ollama, and gateways

- **Status:** Accepted (2026-10-13)
- **Context:** ADR-0005 planned four adapters, including `ollama/ollama/api` for local models. In practice every planned non-Anthropic provider speaks the OpenAI chat-completions wire format: zai and gateways via `base_url`, ollama via its `:11434/v1` compatibility endpoint. Four adapters would normalize the same protocol four times.
- **Decision:** `internal/llm/openai` is the single OpenAI-compatible adapter (`openai/openai-go` + `WithBaseURL`). Provider ids in `internal/llm` presets select kind, endpoint, key env, and default model: `anthropic`, `openai`, `zai`, `ollama`. The planned `ollama/ollama/api` dependency is dropped. This amends ADR-0005; no other framework/SDK adoption (jetify-com/ai, GoAI, langchaingo, eino were evaluated and rejected — alpha-stage or heavyweight).
- **Consequences:** One streaming/tool-call normalization to test; new OpenAI-compatible providers are a preset entry plus optional config. Native ollama features (keep-alive hints, model pulls) stay out of scope until needed.

## ADR-0015: API keys stored in the global config by default

- **Status:** Accepted (2026-10-13)
- **Context:** ADR-0012's secrets stance (env vars / `ref:` indirection only) optimized for servers and CI. golem is a local, single-user tool: the env-var flow required every user to maintain an `export` line in their shell profile, and the daemon inherited only the launching shell's environment — producing invisible startup failures ("server not ready within 5s") and a three-round debugging session. Critically, the env-var flow does not keep keys off disk: the export line lands in `~/.zshrc`, a plaintext file with typically looser permissions than golem's 0600 config.
- **Decision:** The setup wizard writes the validated key directly into `~/.config/golem/config.toml` (`api_key = "sk-..."`, file mode 0600), matching the local-CLI precedent (`gh` hosts.yml, `aws` credentials). `ref:ENV_VAR` indirection and the per-provider env fallback remain supported options. The plaintext warning is removed for the global config; the future project-level `.golem.toml` (committable) will still forbid plaintext keys.
- **Consequences:** Setup-to-first-message works with zero shell integration. Users syncing `~/.config/golem` through dotfiles repos or cloud sync must exclude the file (documented). Credential rotation means editing the config and restarting the server.

## ADR-0016: No approval gate — autonomous tool execution with transcript visibility

- **Status:** Accepted (2026-10-14)
- **Context:** golem is a local, single-user agent on a machine the operator controls. ADR-0010's gate was designed for one prompt per genuinely dangerous command, but real model-issued command lines defeated the whitelist almost every call: `2>/dev/null` and other redirections hit the forced-deny substrings, and chained segments (`cd X && … | head`) required every segment to be whitelisted. A representative session (2026-10-14) prompted 58 times across 67 bash calls — all read-only exploration — and the retry churn contributed to hitting the 50-round turn cap. The gate cost more than the risk it priced.
- **Decision:** Remove the interactive approval gate entirely: the `internal/approval` package, the agent-loop gate, the server's `approval_request`/`approval_response` protocol events (and `approval_timeout` error code), the `[approval]` config section, and the TUI approval modal. Tools execute autonomously. The user-facing contract is observability: every invocation is reported through `tool_call_start`/`tool_call_end` and rendered as a transcript tool block. Execution rails stay: per-command timeouts and output budgets (CONFIG.md `[tools]`).
- **Consequences:** Unattended arbitrary command execution is accepted by design; users who need gating should not run golem with credentials they cannot afford to lose. The wire protocol change is breaking but coordinated (server and clients ship together; pre-1.0 per the changelog header). Old session files containing `approval_request` lines replay harmlessly — unknown event types are skipped. Supersedes ADR-0010.

## ADR-0017: Unbounded tool rounds per turn

- **Status:** Accepted (2026-10-14)
- **Context:** The agent loop capped a turn at 50 provider→tool rounds, killing it with `max tool rounds (50) exceeded` and no summary of work in flight. Session logs (2026-10-14) show the cap hit repeatedly on legitimate long tasks — turns of 53–68 tool calls doing exploration, edits, and `make all` verification — not confused models. Each cut left half-finished work the user had to reconstruct from the transcript. The cap also had no off-switch: `maxRounds` was an unexported constant, and no config key existed.
- **Decision:** Remove the round cap. A turn ends only when the model stops calling tools (a text-only response) or the context is cancelled. Cancellation (TUI interrupt, `Esc`, server shutdown) is the guard against a runaway loop — the same posture opencode takes (no default step limit; user interrupt stops the loop). Compaction-style context management remains out of scope.
- **Consequences:** Long autonomous tasks complete in one turn instead of being chopped at 50 rounds with an error. A genuinely confused model now loops (and burns tokens) until the user interrupts — accepted cost for the local, single-user threat model; the transcript makes the loop visible while it runs. Should a configurable cap return, it should follow opencode's shape: config-driven, and on reaching the limit force one text-only summary round (`toolChoice: none`) instead of erroring out. Test coverage moves from "cap errors the turn" to "the loop runs past the old bound and completes / stops on cancellation".

## ADR-0018: Lazy session creation — a client owns no session until it speaks

- **Status:** Accepted (2026-10-14)
- **Context:** Both clients created a session the moment they connected: the TUI's `connect()` sent `create_session` during `Init()`, and `golem chat` sent it before reading the first input line. Every launch — including one abandoned at the empty composer, or a `chat` that only ever sees `/quit` — minted an empty JSONL session on the server and a phantom row in the session picker (title falling back to the directory name, 0 turns). Session lists accumulated this debris; nothing distinguished "opened the TUI" from "had a conversation".
- **Decision:** Clients create their session lazily, on the first submitted message. The TUI queues the line locally, sends `create_session`, and flushes the queue when `session_meta` arrives (a `set_model` picked before the session existed defers ahead of the flush, preserving wire order); `ctrl+x n` before any session is a no-op — there is nothing to reset. `golem chat` sends `create_session` on the first non-blank, non-`/quit` line and waits for `session_meta` then. The server is unchanged: `create_session` → `session_meta` remains the only entry point to a session.
- **Consequences:** Launching a client and leaving without speaking costs nothing on the server; the session picker lists only sessions that hold a message. A submitted line now waits one round-trip (`create_session` → `session_meta`) before the turn starts — paid once per session, invisible in practice, and shown as a `● creating session` status while pending. `load_session` (picker) is unaffected: resuming a known session needs no create. Protocol is unchanged; the contract documented in PROTOCOL.md gains the client-timing note.

## ADR-0019: Session deletion — cancel, drain, remove the file

- **Status:** Accepted (2026-10-15)
- **Context:** Sessions accumulated with no way out: the picker could list, open, and rename but not delete, so dead sessions lived forever. opencode's shape (`session.remove` after a `turn.cancel`, client-side optimistic row removal) fits golem, but golem's storage differs fundamentally — the append-only JSONL store (ADR-0008) means a turn goroutine (or the 90s title side call) holding an open append path can silently *resurrect* a deleted file via `O_APPEND|O_CREATE`.
- **Decision:** `delete_session` cancels a running turn first, waits for its goroutine to drain (`turnState.done`, bounded by 10s against a wedged provider), removes the JSONL file, and confirms with `session_deleted` to the requester only. Deletion is permanent in the store: `Store.Delete` flags the session id under the same lock as the file removal, and `Append` holds the store lock across its flag-check-open-write sequence — a racing or late writer (a turn goroutine that outlived the drain bound, the 90s title side call) gets `ErrDeleted` instead of re-creating the file, so there is no resurrection window at all. The TUI deletes optimistically (opencode's pattern): `ctrl+d` arms the row — the title swaps to `ctrl+d again to confirm` in the error token — and the second press removes the row immediately and sends the request; any navigation or typing disarms. Deleting the current session resets the client to the lazy-start state (ADR-0018).
- **Consequences:** ADR-0008's append-only discipline is preserved — deletion is a whole-file removal, not record mutation. The confirmation goes to the requesting connection only (no broadcast in v1); other clients reconcile on their next `list_sessions`, and the deleted session's in-flight tail events are documented as droppable. The cancel-drain wait makes `delete_session` synchronous for busy sessions (worst case the 10s bound). A session id, once deleted, is never writable again in this store instance — acceptable because ids are minted ULIDs never reused; a server restart (fresh store) naturally clears the flags, and the files are already gone.

## ADR-0020: AGENTS.md discovery — workspace instructions appended to the system prompt

- **Status:** Accepted (2026-10-15)
- **Context:** The agent's behavior rules lived only in the built-in system prompt. Users could not add project-scoped conventions ("this repo uses table-driven tests", "never touch generated/"), and machine-level preferences had nowhere to live. The AGENTS.md convention (adopted across Claude Code, opencode, Cursor) is the emerging standard: a plain markdown file whose contents are injected as instructions.
- **Decision:** Every turn discovers instruction files and appends them after the system prompt, in order: `~/.config/golem/AGENTS.md` (global, XDG_CONFIG_HOME honored) first, then `<session cwd>/AGENTS.md` (project) last — the nearer file comes later, so it reads as the more specific override. Each file is clipped at 32 KiB with a truncation marker; missing or blank files are ignored. `golem ask` discovers against its workspace root; the server discovers against the session's recorded cwd on every turn (so a file created mid-session applies immediately). `internal/agent.DiscoverInstructions(cwd)` owns discovery; `WithInstructions` threads it into the request's system prompt.
- **Consequences:** Users get per-project and per-machine agent rules with zero config surface — dropping a file is the whole interface. Every turn re-reads the files (two small reads per turn, negligible against provider latency) at the cost of consistent freshness. Prompt injection is a property of the format, not an accident: a workspace AGENTS.md is trusted content, same tier as the source files the agent reads. The global file's precedence-by-position (not by replacement) means both files always contribute.

## ADR-0021: webfetch tool and the golang.org/x/net dependency

- **Status:** Accepted (2026-10-15)
- **Context:** The agent could read the local workspace but not the web — no way to check a doc page, an error message, or a changelog without shelling out through bash curl. A read-only fetch needs three things stdlib alone makes painful: an HTML parser robust to real-world broken markup, strict scheme policing across redirects, and body caps. AGENTS.md requires an ADR for any new dependency; `docs/ARCHITECTURE.md` pins the allowed set.
- **Decision:** Add `internal/tools.WebFetchTool` — a read-only GET for one absolute http(s) URL: 30s timeout, 256 KiB body cap, redirect chain re-checked per hop (a redirect to `file:` or any non-http scheme is refused, as are non-http input URLs), HTML collapsed to visible text with script/style/noscript/template contents stripped. Non-2xx responses error. `golang.org/x/net/html` (html.Parse + a text-node walk, tag-strip fallback on unparseable input) enters the allowed dependency set for this purpose. Registered in the server and `golem ask` registries.
- **Alternatives considered:** stdlib-only tag stripping (fragile against malformed markup, no entity handling, no DOM awareness to skip script bodies); curl through the bash tool (adds a process spawn per fetch, no caps, leaks output to the transcript unbounded).
- **Consequences:** One maintained dependency, aligned with the Go project itself, no transitive baggage beyond what the ecosystem already carries. The tool is read-only: no headers, cookies, or credentials — SSRF surface equals what bash already allows locally, so no additional hardening beyond scheme policing and size/time caps is warranted for the local single-user threat model. HTML pages arrive as scannable text instead of markup soup; JSON/plain pass through untouched.

## ADR-0022: Manual context compaction via an append-only barrier event

- **Status:** Accepted (2026-10-15)
- **Context:** Long sessions grow until the model window fills (ADR-0017 made long turns routine; auto-compaction stays deferred — ROADMAP). Session storage is append-only (ADR-0008): rewriting files to drop old turns would break crash safety and the "storage lines are the wire events" invariant. The user, seeing context pressure, needs a manual escape hatch now; an automatic policy needs tuning data no one has yet.
- **Decision:** A `compact_session` client event triggers a bounded provider side call (60s timeout, 16 KiB summary cap, dedicated summary system prompt) over the session's folded history. On success the server appends a `session_compacted` record — a barrier: folding drops every conversation event before it and replaces the model's context with one synthesized user message (`[Context summary]\n…`); title, turn count, and cwd survive, `firstUserText` resets. On failure (or a refused request — turn running, empty session, unknown session) the client gets `compact_failed` / `error` and the history is untouched. Storage is never rewritten; the barrier replays inside `history` batches so reconnecting clients see the same fold. Clients: TUI `/compact` (composer + ctrl+p palette) and `golem chat` `/compact`.
- **Alternatives considered:** rewriting the JSONL on compaction (violates ADR-0008's append-only invariant and the crash-repair story); automatic compaction at a token threshold (no data to tune it, surprising mid-task context loss — kept deferred in ROADMAP).
- **Consequences:** Compaction is user-triggered and lossy by design: the dropped turns remain in the file (recovery/audit) but never re-enter context. The summary quality bounds how well the model continues; a bad summary is recoverable by starting a new session. One extra provider call per compaction. Fold logic gains one event type; replaying clients must apply the same barrier rule or they would render dropped turns the server no longer sends context for.

## ADR-0023: Reasoning streams must be visible; empty rounds must fail loudly

- **Status:** Accepted (2026-10-15)
- **Context:** GLM models (zai/zai-coding) ship with thinking enabled by default and stream chain-of-thought as `delta.reasoning_content` — a field the OpenAI Go SDK does not model, so it was silently dropped. Reasoning tokens consume the `max_tokens` budget; a hard-thinking round can spend all 16384 tokens invisibly, ending with `finish_reason=length`, zero text, zero tool calls. The agent loop treated that as a clean (if empty) round and emitted `turn_end`: the session appeared completely dead — no text, no error, no status change. A real session (markdown-styling plan) hit exactly this three turns in a row after its context grew past ~54k tokens of accumulated history.
- **Decision:** Two guards. (1) The openai adapter normalizes `reasoning_content` (read from the SDK's `JSON.ExtraFields` metadata) into `thinking_delta` events, so reasoning time renders as the existing "◐ reasoning" TUI state instead of a frozen screen. (2) Rounds that end truncated (`finish_reason=length`) with no text and no tool calls error with `llm.ErrEmptyReasoningRound`; independently, the agent loop turns any no-error round that produced neither text nor tool calls into `agent.ErrEmptyResponse` — a `provider_error`/`error` event reaches the client instead of a silent `turn_end`. The truncation guard stays out of the retry wrapper's transient set: retrying an identical request would burn the same budget again.
- **Alternatives considered:** raising `DefaultMaxTokens` (treats the symptom, costs every user tokens; the empty-round error still needs to exist for whatever cap is set); disabling thinking per-provider (GLM's coding endpoints default it on, and `thinking` is a non-standard body field the SDK does not model — needs the same ExtraFields workaround anyway); auto-retrying with a higher cap (duplicate transcript risk ADR-0017 already worried about, plus unbounded spend).
- **Consequences:** Dead-looking sessions now surface a diagnosable error naming the cause and remedies (raise `max_tokens`, disable thinking, or compact the session — huge input contexts feed the reasoning burn). `thinking_delta` events remain content-free on the wire (PROTOCOL.md unchanged in that respect). One behavioral fix in existing tests: a usage-only round (no text) now errors by design, so the usage-render fixture gained a text delta.
## ADR-0024: Session header — a one-row title strip above the transcript

- **Status:** Accepted (2026-10-15)
- **Context:** The TUI showed nothing about which session it stood in: after `ctrl+x l` switching or a lazy create (ADR-0018), the only identity cue was opening the picker again. A survey of peer agents found no tab bars in terminal clients (tabs belong to the terminal emulator/tmux); the two viable shapes were opencode's on-demand picker modal (already implemented in golem) and Charm crush's always-on one-row header. The header answers "which session am I in" without a keystroke, and golem already holds every datum it needs — except that the generated title only reached clients through `session_list`, so a freshly loaded session rendered untitled until a re-list.
- **Decision:** The chat screen renders a one-row session header above the transcript (below the screen's top padding): the session title in the title token, ` · ` and the cwd's final segment; dim placeholders name the pre-session ("no session yet") and untitled states instead of leaving a blank bar. The row is always rendered on terminals ≥ 16 rows tall (the same anti-jump rule as the status line, decided 2026-10-14) and dropped below that floor so the viewport keeps its minimum height; the resize chrome arithmetic (`resize`/`syncInputHeight`) and the mouse-row mapping (`stickyTopRow`) count the row when it shows. `session_meta` gains an optional `title` field (the folded title at create/load), and the TUI's header state updates from `session_meta`, `session_title` events for the current session, and optimistic picker renames; `clearTranscript` resets it on every session switch. The status line stays agent-state-only — identity lives in the header, state lives in the status line.
- **Alternatives considered:** a tab bar (no precedent among terminal agents; multi-open-session focus and history-relay state for one keypress saved); moving the title into the status line (violates the status-line decision's agent-state-only rule and overloads one strip); OSC terminal-title only (invisible inside the TUI itself).
- **Consequences:** The transcript loses one row on roomy terminals. A client that never runs `list_sessions` still shows the right title (meta carries it; `session_title` events reconcile generation races). Protocol change is additive (`title,omitempty`) — old servers simply omit it and clients fall back to placeholders. Click/selection geometry tests moved from hardcoded `screenPadV` offsets to `stickyTopRow`, which now encodes the header offset too.

## ADR-0025: Automatic context compaction before turn start

- **Status:** Accepted (2026-10-15)
- **Context:** ADR-0022 shipped manual `/compact` and deliberately deferred an automatic policy pending tuning data. That data arrived: the "Continue" session (01M4YQKV…) hit the exact failure the deferral predicted — a folded history grown past a million input tokens fed a reasoning-heavy model until every turn died by reasoning budget burn (ADR-0023), and each death was only recoverable by the user noticing and typing `/compact` by hand. Peer evidence (opencode) shows the same shape: automatic compaction on by default, triggered before each step, with a failed compaction never blocking the turn. golem's manual barrier already exists end to end (summary side call, `session_compacted` record, fold rule, TUI/CLI rendering); what is missing is only the trigger.
- **Decision:** Before each turn starts — in `runTurn`, after the session loads and before the agent loop runs — the server measures the folded history's context bytes (`Session.ContextBytes()`, the byte size of message text, tool-call arguments, and tool results). At or above the threshold the server runs the exact manual compaction path: bounded summary side call, `session_compacted` barrier append, cache invalidation. The turn then proceeds over the compacted history, so the user message always survives (it is appended after the barrier). The threshold defaults to 128 KiB, configurable as `[session] auto_compact_bytes` (0 disables auto compaction — manual `/compact` stays available either way). A failed auto compaction (side call error, timeout, empty summary) emits `compact_failed` and the turn continues on the un-compacted history: compaction is an optimization, never a gate. Triggering is synchronous within the turn: a client watching the stream sees the compaction record before `turn_start`, and interrupts cancel the summary side call with the turn.
- **Alternatives considered:** a provider-reported token trigger (usage lands only at `turn_end` — one turn too late, and token counts differ per provider); an `overflow` trigger on a rejected request (golem providers stream rather than reject up front; without a pre-flight size check the rejection arrives only after a full round is lost); compaction in the background between turns (races user messages; a turn could start against the un-compacted history anyway).
- **Consequences:** Long sessions now self-heal instead of relying on the user's memory. Sessions near the threshold pay one extra provider call per compaction. The barrier is the same record `/compact` writes, so replay, fold, and every client behave identically for manual and automatic compaction. `compact_failed` from an automatic attempt renders the same as a manual failure. Because the trigger fires before the turn's user message is appended, a compaction storm is impossible: the summary message is far smaller than the threshold it just cleared. The interrupt guarantee requires the whole trigger to run inside the turn goroutine (off the connection read loop) and the summary call to derive its context from the turn: an interrupt queued behind the side call must be read, and once read must cancel the call (a 2026-06 fix; originally the trigger ran inline on the read loop with a Background-derived summary context, so an interrupt could neither arrive nor bite).

## ADR-0026: Markdown rendering of assistant output — view-only, in-house block parser

- **Status:** Accepted (2026-10-15)
- **Context:** ROADMAP Phase 3 promised "streaming markdown-ish rendering" but shipped plain text wrapping: assistant messages print raw `**bold**` and `#` markers in both the TUI (`WrapPlain`) and `golem chat`. A planning session surveyed opencode's renderer (marked lexer + remend healing + per-block checksum cache + a small-markdown fast path) and concluded the transferable core is three ideas: separate completed blocks from the live tail, cache rendered blocks by content+width, and fall back to raw text for anything incomplete or unsupported. Dependencies: goldmark or glamour are outside ARCHITECTURE.md's allowed set; a new dependency requires an ADR either way, and a block-level subset (paragraph, heading, fenced code, lists, quote, rule; bold/italic/code/link inline) is small enough (~400 lines) to own outright while keeping full control over terminal output.
- **Decision:** Markdown is a TUI view concern, derived from the already-accumulated assistant text: the wire protocol, JSONL storage, and replay stay raw-text (PROTOCOL.md unchanged). A new `internal/tui/markdown` package owns a block-level parser (completed blocks + a live tail notion), an inline parser (`**bold**`, `*italic*`, `` `code` ``, `[text](url)`), and a renderer that maps tokens to the existing kit palette (headings via the title token, code fences framed by the border token with a dim language label, inline code in the assistant color, quotes dim with a left bar, list markers accented; two new tokens `Code` and `Link` may be added if the existing set proves insufficient). Streaming cost is bounded by the completed/tail split: completed blocks render once and cache by content+width, only the trailing partial block re-renders per delta. An unclosed fence renders as a code block from its opening line; unclosed emphasis renders literally. Tables, HTML, and images are out of scope (v2 candidates, each needing their own decision). Syntax highlighting inside code blocks is deferred.
- **Alternatives considered:** goldmark (full CommonMark fidelity, but a new dependency for a subset a hand-written parser covers, plus less control over incremental/streaming behavior); glamour (terminal-rendered markdown in one call, but streaming re-render of the whole message per delta and another heavyweight dependency); doing nothing (markdown remains unreadable, contradicting the roadmap).
- **Consequences:** Assistant output reads as markdown in the TUI at zero protocol/storage cost. `internal/tui` assistant rendering routes through the markdown renderer, which is injected (no global state). Blocks render only through kit tokens — raw ANSI in the markdown package is forbidden. The CLI (`golem chat`) stays plain: its raw passthrough is deliberate (pipe-friendly) and can adopt the renderer later without protocol change. Height changes from styled rendering flow through the existing span-recompute path (spans are recomputed every event), so click/selection geometry needs no new mechanism.

## ADR-0027: Markdown tables — GFM subset, pipe grid rendering

- **Status:** Accepted (2026-10-15)
- **Context:** ADR-0026 named tables a v2 candidate "needing their own decision." Assistant output routinely compares options in tabular form; rendering pipes raw keeps that unreadable. GFM tables are a block-level shape (header row + delimiter row + pipe rows) that fits the existing block parser's streaming model: a row's trailing newline settles it exactly like a paragraph line, so no new liveness mechanism is needed.
- **Decision:** Extend the `internal/tui/markdown` grammar with GFM-style tables: a pipe-leading header row followed by a delimiter row (`---` with optional `:` alignment markers) opens a table; consecutive pipe rows are body rows; the first non-pipe line ends it. Rows normalize to the header's column count (short rows pad empty, extras truncate — one normalization, stable grid geometry while rows stream in). Pipes without a delimiter row stay a paragraph (the streaming-safe fallback: never flicker a half-streamed table). Rendering is a pipe grid: header row bold through the Fg token, a separator row of `─` runs through the Border token, body cells padded to each column's measured styled width, alignment (`:---`/`---:`/`:---:`) shifting the padding. Cells parse inline markers; cells never wrap — a wrapped cell would misalign the grid, so wide cells widen the table like code rows do. A table block is live while its last row lacks a trailing newline and settles with it; completed tables cache by content+width like every other block.
- **Alternatives considered:** wrapping cells at the terminal width (misaligns the grid when one row wraps and its neighbors do not); rendering tables only after the turn ends (breaks streaming); dropping tables entirely (the v1 stance, superseded here).
- **Consequences:** Assistant tables render as aligned grids in the TUI at zero protocol/storage cost, streaming row by row. The delimiter row is consumed (never shown). Column measurement runs per table render — bounded by the completed/live split. Very wide tables overflow the viewport horizontally instead of wrapping (same posture as code blocks). Nothing changes for other clients: the wire stays raw text.

## ADR-0028: Sticky question line — push-out swap at the rendered window's top

- **Status:** Accepted (2026-10-15)
- **Context:** The sticky line pinned the "governing question" — the latest user message whose block starts above the viewport's *bottom*. Submitting a new question made it governing at once (the follow snap in `turn_start`'s refresh pushes it into view), so the old pin vanished the instant the next chat was submitted and the viewport abruptly regained its hidden row; the pin then reappeared only when streaming pushed the new bar off-screen, snapping back a row. The visible effect: submit → pinned question disappears with a one-row jump → pin re-pops later — the opposite of the intended "keep the last question visible" affordance.
- **Decision:** The pin follows pure push-out semantics against the *rendered window* (`renderedWindow`, the window the transcript actually draws — one row shorter while a pin shows, and pinned to the tail while following): `stickyText` returns the latest user message whose bar starts **above the window's top row**; a bar on or inside the window is transcript content and never a pin. A newly submitted question therefore does not disturb the pin — the pin cedes only when streamed content pushes the newer bar above the top, swapping in place with no height change. `stickyText` scans spans ascending and breaks at the first bar inside the window (spans are ordered, so nothing later is pushed out either).
- **Alternatives considered:** keeping the governing-question rule and suppressing the clear on submit (state would still flip on the next window change — the pop-back snap survives, just delayed); a hybrid "governing unless its bar is visible" (still clears at the follow snap: the moment the new bar becomes fully visible it takes governance and the pin vanishes — the same bug through another path); pinning the last N questions stacked (each extra row is a row the transcript loses; a single governing line was the point); slide-out animation of the old line (terminal cell grids cannot half-scroll a row — the animation cannot exist; only ticker-priced fake motion).
- **Consequences:** Submitting while a question is pinned keeps that pin until the new answer genuinely pushes the new bar off-screen — the push-out feel the sticky line was meant to give. Briefly the pin names the *previous* question while the new bar is still visible; that is the deliberate trade (the newest question is on screen anyway). Invariant: when a pin shows, it names the question whose bar would sit on the row directly above the rendered window — pin and window agree by construction. Scroll regions behave as before: scrolling back until a bar re-enters the window unpins it; the pin re-arms past the top. Click/selection geometry is untouched (row counts unchanged; `stickyTopRow` still derives from `stickyText`). Tests: `internal/tui/sticky_test.go` drives the real composer path (submit → turn_start → streaming) asserting the pin holds across submit and swaps exactly at the window-top crossing; a manual-offset boundary table pins the on-row/above-row edge. View-only: no protocol, storage, or config change.

## ADR-0029: Resumable fold cache — Get resumes from a byte frontier

- **Status:** Accepted (2026-10-16)
- **Context:** The session cache was write-through-invalidate: every turn, rename, and compaction ended with `Store.Invalidate`, so the next `Get` re-opened and re-folded the whole JSONL from line one — O(file) work per turn on the exact path a long session exercises most (each turn's `Get` re-folds everything before it). The cache bought identity checks, not folding. This also made `Get` semantics ambiguous: a hit could serve a session missing its most recent turns, which is why the server had to remember to invalidate everywhere.
- **Decision:** A cache entry keeps the live `folder` plus a folded frontier (byte offset of the last newline-terminated line) and any unterminated trailing bytes. `Get` stats the file: unchanged → snapshot; grown → seek to the frontier and fold only the new complete lines; shrunk (external rewrite) → full reload. Snapshots are built from a shallow clone, so closing a trailing partial turn in a view never mutates the live fold; an unterminated tail (a crash mid-write) folds into snapshots only and is never consumed as a frontier line — when its newline lands, the line refolds from the frontier exactly once, never doubled. `List` summaries cache per file keyed by (size, mtime). The server drops its post-turn/rename/compaction `Invalidate` calls; `Store.Invalidate` remains for callers that know the file changed shape behind them.
- **Alternatives considered:** write-through cache maintenance inside `Append` (the folder cannot fold its own output safely — the event being appended is the wire event, but Append is generic over `any` and used for raw writes); invalidation everywhere (status quo — O(file) refold per turn and an invariant the server must uphold by hand); mmap (premature for megabyte files).
- **Consequences:** Per-turn folding drops from O(file) to O(new lines); a 500-turn cold replay folds in ~3 ms (Phase 7 budget: 100 ms — `TestReplayBenchmark_500Turns`). `Get` is now always fresh: a hit returns the session as it exists on disk, with appends from other processes folded too. Sessions share immutable message strings between the live fold and snapshots (production callers only read `Messages`). Shrink detection needs a stat per `Get` — one `os.Stat` against a saved re-fold. `Invalidate` stays exported: the write-through semantics it guaranteed (a subsequent `Get` re-reads from disk) still hold, and tests/tools may use it; only the server's reflexive per-turn calls are gone.

## ADR-0030: The compaction barrier is a context rule, not a view rule

- **Status:** Accepted (2026-10-16)
- **Context:** The TUI's history replay applied the ADR-0022 barrier fold to the *view*: `foldReplayEvent` reset the block list at every `session_compacted` record, exactly as the server's fold drops context. That read as correct symmetry while compaction was manual and rare. ADR-0025 made compaction automatic at 128 KiB — long sessions hit the barrier a dozen or more times, and the visible effect became a user report: "loading a past session, I can't scroll from the beginning to the end." The transcript the picker opened showed only the tail after the last summary; the session's beginning was unreachable by any amount of scrolling, because it was never rendered at all.
- **Decision:** The barrier's drop rule scopes to the model's context only. The TUI transcript — live and replayed — renders the barrier as the dim summary block *in place* and keeps every turn before it; the session file and `history` batches already carry those events (storage is append-only, the barrier never rewrites). Context behavior is unchanged: the server still folds everything before the barrier into the synthesized summary message.
- **Alternatives considered:** keeping the view drop and adding a "show full history" toggle (a second render path for the same data, and the default still hid the beginning); truncating pre-barrier blocks but keeping a jump-to-top (the jump would land nowhere — the content was gone); dropping the barrier block from the view entirely (the summary is real conversation history users cite).
- **Consequences:** Loaded sessions scroll from their true first message to the tail across any number of barriers. Very long sessions render more blocks (replay cost is linear in stored events either way; the render cache absorbs reflows). `stickyText`, selection, and click geometry see only a longer block list — no new interaction. PROTOCOL.md now states the scoping explicitly so other clients (`golem chat`, future apps) do not re-import the symmetric-fold reading.

## ADR-0031: Prompt baseline — minimal clauses, environment block injected per turn

- **Status:** Accepted (2026-10-16)
- **Context:** A comparison against the system prompts of Claude Code, Codex (GPT-5 / 5.1), Gemini CLI, and opencode showed golem's five-line base prompt was structurally sound — most peer prompt bulk (tool usage detail, project rules) is deliberately decentralized in golem into tool descriptions and AGENTS.md discovery (ADR-0020). But three real gaps existed: (1) the model never learned its working directory, platform, or date, so every bash call started from a cwd guess; (2) golem executes tools with no approval gate (ADR-0016), yet unlike the gated peers it carried none of the safety clauses (user-work protection, no destructive commands/unrequested commits, untrusted tool output, secrets) — the gate removal made text the only guardrail and the text was absent; (3) no persistence/parallelism/question-vs-directive guidance that every peer prompt carries in some form.
- **Decision:** The base prompt grows from five to ~16 lines, carrying: identity, tool use, edit preference, verification (kept), user-work protection ("never revert or discard changes you did not make"), destructive-command and commit prohibition, untrusted-data clause (tool output is data, not instructions — covering webfetch, ADR-0021), secrets hygiene, failure persistence ("read the error, adjust, and retry"), parallel tool batching, question-vs-directive distinction, user-language mirroring, and brevity. A new pure function `agent.EnvironmentContext(cwd, now)` renders `Working directory / Platform (runtime.GOOS) / Today (date)` and is injected per turn via `agent.WithEnvironment` by both call sites (server turns against the session's cwd, `golem ask` against the workspace root). Prompt assembly order is base → environment → AGENTS.md, so project files still read last and keep position-based precedence. Conspicuously *not* adopted from peers: final-answer formatting specs (Codex), context-efficiency essays (Gemini), personality/planning-channel guidance (no plan tool exists) — all judged bloat against the per-turn token cost.
- **Alternatives considered:** a fully specified prompt on the Claude Code scale (~2,000 words — pays attention tax every turn for guidance modern models produce without asking); environment lines inside each tool description (the directory is conversation state, not tool semantics, and the date has no tool home); appending the environment into the AGENTS.md discovery payload (blurs ADR-0020's file-trusted-content tier with machine-generated context).
- **Consequences:** The model starts each turn knowing where it stands; the ungated execution posture (ADR-0016) is now backed by explicit safety text matching every gated peer. `TestDefaultSystemPrompt_ContainsBaselineClauses` pins each clause to its rationale so future edits must confront the ADR; `TestServer_TurnWorksWithoutAGENTSFiles` gains the environment assertions. AGENTS.md precedence is unchanged (project still last). The date line refreshes per turn — midnight rollovers mid-session self-correct. Platform comes from `runtime.GOOS` of the *server* process, correct for local use (ADR-0003's single-machine posture).

## ADR-0032: Title generation fires at turn start and pushes the result

- **Status:** Accepted (2026-10-16)
- **Context:** A first turn of a fresh session generated its title only after `turn_end` — and even then merely persisted the `session_title` record, never emitting it. Perceived latency stacked three ways: the whole agent turn (tool loops can run for minutes) delayed the side call; the side call itself adds seconds; and the client never learned the title at all — the TUI header showed "untitled session" until the user happened to open the session picker (its `list_sessions`) or reload. The first user message names the task the moment the turn starts; nothing about the answer is needed to title it.
- **Decision:** `runTurn` fires the title side call alongside the agent loop (not after it) whenever the session is untitled and a title text exists (the turn's own message on the first turn, else the session's folded `firstUserText`). On success the server pushes the persisted `session_title` to the connection that started the turn — the same event `rename_session` confirms with, folded by clients as a session record (the TUI header/list already handle it). A `titleRuns` map guards overlap: one in-flight side call per session, so back-to-back turns of an untitled session (a failed generation retrying) cannot double-fire or double-persist. Failure behavior is unchanged: log to stderr, no record, retry on the next turn.
- **Alternatives considered:** keeping the post-`turn_end` timing and only adding the push (leaves the dominant term — the turn's own length — in the latency); pushing to all connections instead of the requesting one (the server tracks no subscriber set per session today; `session_list` already reconciles other clients — the rename path sets the precedent of requester-only emission); client-side polling (`list_sessions` after `turn_end`) — a TUI-only patch leaving `golem chat` and future clients polling forever.
- **Consequences:** The title lands (and the TUI header updates) within one side call of the first message, regardless of how long the agent works. Two provider calls now run concurrently at turn start on an untitled session — rate-limited providers may order them; the side call keeps its 90 s bound and retry ladder (ADR: title bounds in `internal/server/title.go`). The `session_title` push interleaves with turn events in any order (both goroutines write the same connection through `connWriter`'s lock); PROTOCOL.md now says so, and clients must fold it as a session record, not a turn event — additive per forward-compatibility rules, and both shipped clients already do. Storage shape is unchanged: one `session_title` record per successful generation.

## ADR-0033: Walk hygiene and read windows — skip lists, root .gitignore, binary refusal, offset/limit

- **Status:** Accepted (2026-10-17)
- **Context:** grep/glob pruned only `.git` from their walks — every dependency tree (`node_modules`, `vendor`, `target`), build output (`dist`, `build`, `bin`), cache, and golem's own `.worktrees/` was scanned and its matches flooded results as noise (token cost and model confusion), while ripgrep-based peers get `.gitignore` compliance for free. read returned whole files with only the tail-cut 16 KiB output budget as defense — "read lines 100–140" still pulled the entire file into context. read also happily returned binary content as mojibake lines. Peer review: Claude Code/Codex ship ripgrep (gitignore + parallelism, external binary accepted); Gemini CLI ships hardcoded exclude lists plus extension blocklists in pure TypeScript; golem's no-external-binary posture (AGENTS.md dependency rules) rules out the first and leaves the second. Binary detection used a NUL probe, which misclassifies UTF-16 text as binary; stdlib `net/http.DetectContentType` (WHATWG sniffing) gets that right at identical cost.
- **Decision:** (1) grep and glob walks prune a named constant skip list — VCS internals (`.git`, `.hg`, `.svn`), dependency trees (`node_modules`, `vendor`, `bower_components`), build output (`target`, `dist`, `build`, `bin`, `out`), caches (`__pycache__`, `.venv`, `venv`, `.next`, `coverage`, `.worktrees`), IDE dirs (`.idea`, `.vscode`). (2) Both walks honor the workspace root's `.gitignore` — an in-house parser supporting `*`, `?`, character-free segment globs, trailing-slash dir-only rules, anchored vs unanchored semantics; `!negation`, interior `**`, and nested `.gitignore` files are out of scope (unsupported lines are skipped, never fatal). (3) glob drops files by extension blocklist (images, archives, executables, fonts, media — the noise read would refuse anyway); grep instead sniffs opened files by content, now via `http.DetectContentType` instead of the NUL probe. (4) read refuses binary files with a message pointing the model at bash (`file`, `strings`). (5) read takes `offset` (1-based line) and `limit` (line count) arguments; omitted/0 mean from-the-top and to-the-end, negative values error, and numbering reflects the true file line numbers. Tool descriptions grew one sentence each (edit failure guidance: read first, add context; bash: prefer dedicated tools, chain with `&&`) — behavior detail stays in tool descriptions per ADR-0031's decentralization.
- **Alternatives considered:** shelling out to ripgrep (violates the no-external-binary posture; bash already covers rg-installed hosts as the escape hatch); honoring nested .gitignore files (correctness for monorepos, at parsing complexity this baseline skips); config-driven skip lists (no user asked; the constant list ships the Gemini CLI baseline); UTF-16 support in read (DetectContentType fixes detection, but no code agent works in UTF-16 sources — not worth a decoder).
- **Consequences:** Search results are workspace signal, not vendor noise; `.worktrees/` no longer duplicates every hit (previously masked only by a local `.git/info/exclude`). Models can address line windows of large files instead of ingesting them whole — the biggest single token saving of this ADR. Existing repos whose source lives under a skip-listed name (e.g. a `bin/` containing sources) will see those paths excluded from glob/grep; the bash tool remains the workaround, same as any other skip disagreement. gitignore support is deliberately a subset; users relying on negation or nested files keep seeing those paths (skip, not fail). The extension blocklist is name-based: a misnamed binary still sneaks past glob but read refuses it by content — the two checks compose. Skip-list membership is by directory *name*, so a project directory literally named `vendor` holding first-party source is excluded; golem itself hits this (`vendor/` doesn't exist here, but `bin/` holds binaries — the trade stands and bash covers it).

## ADR-0034: Session fork — copy raw JSONL lines through a turn boundary

- **Status:** Accepted (2026-10-16)
- **Context:** Sessions are single files that only ever grow; the one escape hatch for "try a different direction from here" was starting over. opencode's fork (SQLite) copies settled history rows into a new session with `fork_session_id`/`fork_boundary` columns and increments a `"title (fork #N)"` suffix. golem's store is append-only JSONL (ADR-0008): the equivalent operation is copying the parent's raw lines into a new child file — no rows, no batches, no transaction. opencode's boundary is a message id; golem's atomic unit is the turn (`turn_start`…`turn_end`), and a turn goroutine may be mid-append, so the boundary must be a *completed* turn.
- **Decision:** `fork_session {session, turn?}` asks the server to fork a session. The boundary is turn-granular: `turn` names a turn ULID to fork through (that turn's `turn_end` inclusive); omitted, the boundary is the session's last completed turn. A session with zero completed turns is refused (`invalid_request`), as is a busy session (a running turn's appends would race the copy) or an unknown turn id. The child file is written once, in order: (1) a `session_meta` header with a fresh ULID and the parent's cwd, (2) a `session_forked` lineage record `{parent, through_turn}`, (3) the parent's raw lines through the boundary with each line's `session` field rewritten to the child id (Go's map marshal is key-sorted, so rewriting is deterministic), (4) a `session_title` record with the fork title when the parent is titled — `"X (fork #N)"`, N = 1 + the max existing suffix among siblings with the same base (opencode's rule). The parent file is never touched. The server confirms with `session_forked {session, parent, title}` to the requester only (ADR-0019's pattern). Because the copy includes any `session_compacted` barriers, compaction context rules (ADR-0022/0025/0030) apply to the child unchanged — a stated test, not an accident. The folder skips `session_forked` as an unknown type, so old servers can replay child files and new servers replay parent files written before this ADR.
- **Alternatives considered:** message-granular boundaries à la opencode (golem's fold and turn bookkeeping are turn-shaped; mid-turn splits would copy assistant/tool fragments without their turn envelope); referencing the parent instead of copying (violates ADR-0008's file-is-the-transcript rule and couples a child's lifetime to its parent's — deletion would orphan it); rewriting events into a normalized child format (the copy must be byte-faithful so `history` replay and the fold see the identical conversation); a separate lineage index file (the lineage record inside the file keeps everything one-file-one-session).
- **Consequences:** Fork cost is one sequential read+write bounded by the boundary prefix — no transaction, no batch sizing. Child sessions appear in `session_list` with no registration step (the store lists the directory). Fork titles increment across siblings even when the parent is a fork itself (regex strips an existing suffix first, so forks of forks stay shallow: `"X (fork #1)"` → `"X (fork #2)"`). The child's `history` batches are self-referential (session field = child id) — clients never see the parent id in events. v1 excludes: a turn-picking UI (the protocol's `turn` field is the extension point; the TUI always forks through the last completed turn), `/fork` in `golem chat`, and fork-tree browsing in the picker. Deletion interplay (ADR-0019) is safe by construction: `Store.Fork` checks the parent under the store lock, and a deleted parent fails the existence check.

## ADR-0036: Interruptions render as deliberate stops, not provider failures

- **Status:** Accepted (2026-10-18)
- **Context:** Pressing esc/ctrl+c during a running turn cancelled the turn context, and the cancellation propagated as-is: the provider adapter wrapped `context.Canceled` with its own prefix and — because adapters tag every status-less failure for the retry ladder — `ErrTransient`; the agent loop emitted that chain; the server mapped every agent error to `provider_error`; the TUI rendered the message verbatim. The user saw `error: openai stream: context canceled: transient provider failure` in red after deliberately stopping a turn — a stop the user initiated reading as a crash. The same leak could surface from delete_session's cancel and server shutdown, and an interrupt killing an in-flight auto-compaction summary (ADR-0025) additionally emitted a `compact_failed` "skipped" notice after the stop.
- **Decision:** Three layers, each classifying rather than string-matching. (1) `agent.ErrInterrupted` is a new exported sentinel; the loop's fatal-error branch collapses any provider cancellation chain onto it (`ErrInterrupted: context canceled`) when the turn context is done, and a cancellation between tool calls — previously a silent stop — now emits it too. (2) The server maps `errors.Is(err, agent.ErrInterrupted)` to the new wire code `interrupted` (constant `golemclient.CodeInterrupted`); every other loop/provider failure keeps `provider_error`. `errorOf` gains the agent chain unchanged, so `history` replay folds cancelled turns identically. An interrupt-cancelled auto-compaction emits nothing: the turn's `interrupted` event is the last word. (3) The TUI folds `error` events through `errorBlock`, which renders `interrupted` as a dim `⏹ stopped — the turn was cancelled (esc / ctrl+c); the session is ready for your next message` notice — live and replayed — while every other code keeps the red `error:` line. The stored JSONL line is untouched: the code, not the rendering, is the contract.
- **Alternatives considered:** TUI-side string matching on "context canceled" (fragile: adapters phrase their prefixes differently and the retry wrapper's wording can drift; AGENTS.md forbids string-matching errors); suppressing the error event entirely and emitting a synthetic `turn_end` (breaks PROTOCOL.md's turn-termination semantics and hides the stop from `golem chat` and future clients); classifying in the provider adapters (they cannot distinguish the caller's interrupt from a network drop at their layer — only the loop owns the turn context); a dedicated `turn_interrupted` event type (additive but redundant: the error event already carries a code slot and both shipped clients fold it).
- **Consequences:** A stopped turn reads as a stop in every client that honors the code, including replays of old sessions (their stored lines already carry `provider_error` with cancellation text — those still render as errors; only new interruptions carry the code). `golemclient.CodeInterrupted` is the fourth exported error-code constant-free slot's first use; PROTOCOL.md's error table documents it. Busy-state teardown, the drain flag, and the interrupt ladder's key handling are unchanged. Tests pin each layer: `TestLoop_Cancel_EmitsErrInterrupted` (agent), `TestServer_InterruptEndsTurnGracefully` + `TestAutoCompact_InterruptCancelsSummarySideCall` (server), `interrupt_test.go` (TUI, live and replay, both codes).

## ADR-0037: Compactions announce themselves — `compacting` before the summary side call

- **Status:** Accepted (2026-10-18)
- **Context:** A user report: with auto-compaction on (ADR-0025, default 128 KiB), submitting a message on a long session looked frozen — nothing animated, nothing explained, for up to the summary side call's 60 s bound. The status strip had no case for compaction: manual `/compact` and the automatic pre-turn trigger both run the side call *before* any event the strip knows (`turn_start` is the first turn event; `session_compacted` lands only at the end), so the strip sat on the static idle dot across the whole wait. The protocol already solved this exact shape once: `retry` is "emitted before the wait so clients can render a retrying state instead of a frozen one" — compaction lacked its counterpart. A second gap rode along: the summary side call is interrupt-cancellable with the turn (ADR-0025), but the TUI's interrupt keys (`esc`/`ctrl+c`) only fired when `turnActive` was set — during the pre-turn window the user had no visible or *reachable* way to stop a compaction they could see hanging.
- **Decision:** A new server→client event `compacting {session}` is emitted — and persisted — immediately before the summary side call starts, in the shared `compactSession` body both the manual and automatic paths use. It carries no turn, folds to nothing in conversation state, and resolves with the next `session_compacted` or `compact_failed` on the session (the automatic path's following `turn_start` supersedes it on the strip). Clients render it as a live state: the TUI's strip shows an animated `compacting context` (below reasoning, above thinking, in the priority ladder), arms the animation ticker, counts it as working for the OSC 7501 tab dot, treats it as interruptible for `esc`/`ctrl+c`, and restores it when a busy session's replay ends on the announcement; `golem chat` prints a one-line notice. Persistence follows the existing invariant (storage lines are the wire events): the announcement is appended before emission, so replay ordering is exact — and a replay that ends on the announcement is precisely a session caught mid-side-call.
- **Alternatives considered:** client-side timers guessing at a compaction (the client cannot know the threshold or whether the trigger fired — pure guesswork); emitting `session_compacted` early with a placeholder summary (corrupts the barrier contract and the fold); making the TUI optimistic about `/compact` locally (covers only the manual path, and switching sessions or reconnecting loses the state); streaming the summary as it generates (deltas of a summary nobody reads, and the barrier record is atomic by design).
- **Consequences:** The frozen window is covered end to end for both compaction paths in every client that folds the event (additive per forward-compatibility rules; unknown-type clients ignore it and are no worse off than before). One extra persisted line per compaction — negligible against the megabyte histories compaction exists to shrink, and it doubles as an audit trail of when compactions ran. Interrupts during the pre-turn window now work visibly: the cancel kills the side call (ADR-0025), the turn's `interrupted` error is the last word (ADR-0036). Tests pin each layer: `TestRoundTrip_Compacting` (wire), `TestCompact_AnnouncesCompactingBeforeSideCall` + `TestAutoCompact_AnnouncesCompactingBeforeTurn` + storage-order assertions (server), `TestFold_CompactingAnnouncementChangesNoState` (session fold), `TestStatus_Compacting*` + the resume table (TUI), the chat progress lines (CLI).
